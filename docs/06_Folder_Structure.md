# Folder structure

```text
Ar-Multi Flascards/
├── index.html                  App entry HTML (loads src/main.js)
├── package.json                Scripts and dependencies (see below)
├── vite.config.js              App's dev/build config — HTTPS dev server + asset middleware
├── vite.tools.config.js        Separate config for the authoring-tool pages (plain HTTP)
├── vercel.json                 Vercel build/deploy settings
├── .env.example                Template for local .env (never committed with real values)
├── .gitignore / .gitattributes Excludes assets/, node_modules/, secrets; marks binaries
│
├── src/                        The app itself — see below
├── tools/                      Content-authoring scripts and pages — see below
├── public/                     Small static files Vite DOES bundle into dist/ — see below
├── assets/                     The runtime asset library (NOT committed to git) — see below
├── backups/                    Working backups written by tooling (git-ignored)
├── dist/                       Build output (git-ignored, regenerated by `npm run build`)
├── docs/                       This documentation set
└── node_modules/               Installed dependencies (git-ignored)
```

## `src/` — the application

Everything here is bundled by Vite and shipped to users.

| File | Responsibility |
| --- | --- |
| `main.js` | App entry point. Loads `manifest.json`, renders the category grid and search bar, and hands off to `ar-view.js` when a category is opened. Owns the Back button and the home-screen loading/error states. |
| `ar-view.js` | The entire AR session for one open category: camera start/stop, per-card MindAR anchors, gesture controls (drag/pinch/hold/tap), the on-screen buttons (speaker, reset, Place Here/Return to Card, help), and the render loop. The largest file in the app. |
| `placement.js` | Pure placement/orientation math and GLTF loading, shared verbatim between the AR runtime and the `tools/place-models.html` authoring page — see [04_Data_Model.md](04_Data_Model.md) for the placement data it interprets. |
| `placement-manager.js` | The "Place Here" gyroscope-only room-pinning illusion. Framework-free apart from three.js; has no DOM/UI code of its own — see [12_Known_Issues_and_Limitations.md](12_Known_Issues_and_Limitations.md). |
| `audio-player.js` | The single shared `<audio>` element used for every card's spoken-name clip, plus the iOS autoplay-unlock trick. |
| `deck-search.js` | Pure, DOM-free search/filter logic over the manifest — normalizes text (accent/case-insensitive) and ranks deck-name hits above card-name hits. Testable from Node (see `tools/check-search.mjs`). |
| `camera-error.js` | Turns a failed `getUserMedia`/MindAR start into a specific, human-readable error message (permission denied, no camera, camera busy, etc.). |
| `transform-store.js` | Small generic `localStorage` key/value wrapper used to remember each card's user-applied rotation/scale/offset between visits. |
| `config.js` | The one file that knows how to turn an asset's relative path into a full URL, using `VITE_ASSET_BASE`. Every other file that needs an asset URL imports from here. |
| `styles.css` | All app styling (the "toy-box" kid-friendly visual design — see project memory notes). |

## `tools/` — content-authoring pipeline (not shipped)

None of this ships in `dist/`; it exists to turn raw card/model/audio files
into the compiled data the app needs. See
[14_Admin_Guide.md](14_Admin_Guide.md) for how to use it end to end.

| File | Purpose |
| --- | --- |
| `validate-assets.mjs` | Checks the `assets/cards|models|audios` folders for naming/pairing problems and writes `assets/manifest.json`. Run via `npm run validate`. |
| `check-targets.mjs` | Reads compiled `.mind` files and reports which cards are unlikely to track well (see [10_Testing_Guide.md](10_Testing_Guide.md)). Run via `npm run check`. |
| `check-search.mjs` | Node-side sanity check for `deck-search.js`'s search ranking. Run via `npm run check:search`. |
| `check-cdn.mjs` | Verifies a deployed CDN bucket has every expected asset file, with correct size/CORS/cache headers, and that the private `*-original/` folders are not public. Run via `npm run check:cdn`. |
| `compress-models.mjs` | Draco-compresses and shrinks `.glb` models in place (backing up originals to `assets/models-original/`). Run via `npm run compress`. |
| `resize-cards.mjs` | Downscales oversized card images (backing up originals to `assets/cards-original/`). Run manually per deck. |
| `upload-assets.mjs` | Syncs the four runtime asset directories to Cloudflare R2 via `rclone`. Run via `npm run upload`. |
| `receiver.mjs` | Tiny local HTTP server the browser-based tool pages POST their compiled output to (see [05_API_Documentation.md](05_API_Documentation.md)). Run via `npm run receiver`. |
| `compile-targets.html` | Interactive browser page: pick decks, compile their `.mind` target files. Served by `npm run tools`. |
| `place-models.html` | Interactive browser page: the placement editor — solve, review, and hand-tune where each model sits on its card. Served by `npm run tools`. |
| `compile-headless.js` | Same job as `compile-targets.html` with no UI, for scripted/agent-driven runs. |
| `solve-headless.js` | Same job as the "Solve deck" step of `place-models.html` with no UI. |
| `orient-solver.js` | The silhouette-matching algorithm both the interactive editor and the headless solver call into. |
| `load-card-image.js` | Shared helper: mattes a card image onto a white background before it's used for compiling/solving (see the "Transparent card art" note in the README). |

## `public/` — small static files Vite DOES bundle

Unlike `assets/`, anything in `public/` **is** copied into `dist/` on every
build. Only things the app genuinely needs at the same origin as the built
JS live here.

| Path | Purpose |
| --- | --- |
| `draco/draco_decoder.js`, `draco_decoder.wasm`, `draco_wasm_wrapper.js` | Three.js's own Draco mesh decoder. Every model in the library is Draco-compressed, so this must ship with the app and stay at a stable path (`src/placement.js` points `DRACOLoader` at `/draco/`) — it cannot be moved to the CDN with the rest of the assets. |

## `assets/` — the runtime asset library (git-ignored, ~800 MB of runtime data)

Not committed to git (`.gitignore` excludes all of `assets/`). Exists on the
authoring machine and, in production, on object storage/CDN instead of in
the git repo or the build output.

```text
assets/
├── manifest.json              Generated by npm run validate — see 04_Data_Model.md
├── placements.json            Hand-tuned + solver output — see 04_Data_Model.md
├── cards/<category>/<card>.{jpg,jpeg,png}      Card scans/photos shown in the app
├── models/<category>/<card>.glb                Compressed 3D models shown in AR
├── audios/<category>/<card>.{mp3,m4a,ogg,wav}  Spoken-name clips (optional per card)
├── targets/<category>.mind                     Compiled MindAR image-recognition files
├── cards-original/<category>/...   Pre-resize backups — LOCAL ONLY, never uploaded
└── models-original/<category>/...  Pre-compression backups — LOCAL ONLY, never uploaded
```

<!-- prettier-ignore -->
> [!WARNING]
> `cards-original/` and `models-original/` are print-master backups that must
> never be made public. `tools/upload-assets.mjs` only ever uploads the four
> runtime directories by name (never a wildcard over `assets/`), and
> `tools/check-cdn.mjs` actively probes for and fails on either folder being
> reachable on the live bucket.

## `backups/` — working backups written by tooling

Git-ignored. Holds timestamped `.bak` copies some tools write before
overwriting `assets/manifest.json` / `assets/placements.json`. Safe to
delete; nothing reads from it automatically.

## `dist/` — build output

Git-ignored, regenerated by `npm run build`. Contains the bundled app
(`assets/index-*.js`, `assets/index-*.css` — note this is Vite's own
`assets/` output folder for JS/CSS, unrelated to the project's `assets/`
asset library, a naming collision that `vite.config.js`'s preview middleware
explicitly works around) plus a copy of `public/draco/`. Deployed as-is to
the static host — see [09_Deployment_Guide.md](09_Deployment_Guide.md).
